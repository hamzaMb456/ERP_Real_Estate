## Prédiction : temps de déploiement sur compte AWS réel (28 oct 2026)

⚠️ **Extrapolation, pas une mesure** — fondée sur les chiffres émulateur (synth 95.0 s ; deploy
idempotent 61.7 s ≈ 2.7 s/stack ; sur l'émulateur, les aller-retours CloudFormation répondent
quasi instantanément, contrairement au cloud réel). À re-mesurer au premier deploy réel via
`deploy-timed.mjs` (le script fonctionne inchangé : seule la variable `AWS_ENDPOINT_URL` n'est
plus fixée) — la valeur réelle ira dans le CloudWatch réel et remplacera « ~62 s » dans le CV.

| Scénario | AWS réel (prédit) | Hypothèse clé |
|---|---|---|
| `cdk synth` | ~95–150 s | CPU-pur, identique au local |
| Deploy idempotent 23 stacks (séquentiel) | **3–7 min** | ~10–25 s de CreateChangeSet/Execute par stack (aller-retours CFN réels) |
| Deploy idempotent avec `--concurrency 4` | **2–3 min** | déploiements parallèles |
| Premier déploiement à froid (tout créer) | **10–20 min** | créations réelles (20 tables, Lambdas, AppSync, rôles) + `cdk bootstrap` one-off |
| Patch d'un seul stack | 1,5–3 min | un seul aller-retour CFN |
| `--hotswap` (dev, Lambda seul) | ~40–90 s | court-circuite CFN (dev uniquement) |
| Pipeline CI GitHub Actions complet (`npm ci` + synth + deploy) | **~8–12 min** push→vert | cache npm |

Consensus à citer en entretien : le deploy complet passe de **~62 s → ~4–6 min** (séquentiel),
**~2–3 min** en `--concurrency 4`. Incertitude CloudFormation : ±30 % sur les no-op.
